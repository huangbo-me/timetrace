# 法定工作日、弹性工时与历史性能设计

## 背景与目标

真机数据表明，工作地点当前保存的星期掩码可能因界面含义不清而排除正常工作日，导致整段会话被归为休息日加班。现有加班算法也没有接入项目已有的 `ChinaWorkCalendar`，无法正确处理中国大陆法定节假日和调休工作日；排班模型只有固定上下班窗口，不能表达“每日工作满 8 小时、期间固定休息 3 小时”的弹性工时。

本次同时解决以下问题：

1. 默认使用中国大陆法定工作日判断，保留自定义每周工作日能力。
2. 增加固定上下班与弹性工时两种模式，以及用户可选的固定休息时长。
3. 将排班修改范围改为居中弹窗，并显示真正会被历史重算影响的记录数。
4. 减少历史列表重复计算，并修复瀑布流末尾只剩单侧卡片的问题。

不增加服务器接口、薪资倍率、迟到早退判断、实际休息打卡或法定节假日工资倍数。

## 已确认的产品口径

### 工作日来源

- 默认规则为“中国大陆法定工作日”。
- `ChinaWorkCalendar` 中的法定节假日属于休息日；调休工作日属于正常工作日。
- 其他普通日期按周一至周五工作、周六周日休息处理。
- 特殊轮班用户可以切换为“自定义每周工作日”，此时才显示星期选择器。
- 当前离线表只明确覆盖 2026 年；其他年份沿用现有普通周末回退，并在界面和文档中说明。
- 不读取系统日历或申请 EventKit 权限。系统日历事件不是可靠、权威的调休数据源。

### 工时模式

排班启用后提供两种模式：

1. **固定上下班**：用户选择上班时间、下班时间和休息时长；结束时间早于开始时间仍表示次日下班。
2. **弹性工时**：用户选择每日标准工时和休息时长，不设置固定上下班边界。

每日标准工时和休息时长都以 30 分钟为步长。每日标准工时可选 0.5–16 小时，休息时长可选 0–12 小时。弹性工时默认标准工时为 8 小时；旧排班和旧快照兼容值为固定上下班、自定义每周工作日、休息 0 小时，以免升级后静默改变历史结果。新工作地点默认中国大陆法定工作日、固定上下班 09:00–18:00、休息 0 小时。

### 休息与加班

- 正常工作日会扣除用户选择的休息时长。
- 休息日不扣除休息时长；不属于前一工作日夜班窗口的在岗时间全部计入休息日加班。
- 固定上下班模式每个班次只扣一次休息时长，包括跨午夜夜班。休息从正常班次内的已记录时长中扣除，不抵消班次边界外的早到或晚走加班。
- 弹性工时按会话时区的自然日逐日计算。每个正常工作日最多扣一次休息时长，再用有效工作时长与每日标准工时比较。
- 弹性工作日加班显示为“工作日加班”，不虚构早到或晚走；固定上下班继续显示早到和晚走。
- 有效工作时长最低为 0。

示例：弹性工时标准 8 小时、休息 3 小时，正常工作日 10:00 到达、21:00 离开，在岗 11 小时，扣除休息后有效工作 8 小时，加班为 0。

## 领域模型与兼容

### 新增值类型

- `WorkCalendarMode`
  - `chinaStatutory`
  - `customWeekdays`
- `WorkScheduleMode`
  - `fixedWindow`
  - `flexibleDuration`

### `ActivityTrigger` 新字段

- `workCalendarModeRaw`
- `workScheduleModeRaw`
- `standardWorkMinutes`
- `restMinutes`

字段使用 SwiftData/CloudKit 可兼容的默认值。旧数据迁移后按 `customWeekdays + fixedWindow + restMinutes=0` 解释；创建新工作地点时由用例显式写入新默认值。备份结构增加可选字段，读取旧备份时采用相同兼容值。

### `WorkScheduleSnapshot` 扩展

快照和排班修正事件增加：

- 工作日规则；
- 工时模式；
- 每日标准工时分钟数；
- 休息分钟数。

旧进入事件和旧排班修正缺少这些键时，按旧口径解析，不能因为 App 升级而自动套用法定日历或休息扣除。最新修正事件仍具有最高优先级；损坏的最新修正仍停止回退，避免猜测历史排班。

## 加班计算

`WorkScheduleCalculator` 先通过一个统一的日历策略判断每个日期是正常工作日还是休息日，再按工时模式计算：

### 固定上下班

1. 生成所覆盖日期的班次窗口，夜班归属于班次开始日。
2. 班次按开始日判断工作日属性：工作日开始的夜班跨入休息日后仍属于该工作班次，休息日开始的夜班整个班次均为休息日加班。班次窗口以外的时间按其实际自然日判断。
3. 正常工作日保留现有早到、班次内、晚走分段。
4. 从当班的正常工时中扣除 `restMinutes`，最低为 0；早到和晚走时长不被休息抵消。

### 弹性工时

1. 按会话时区自然日切分在岗区间。
2. 休息日整段计入休息日加班。
3. 正常工作日计算 `有效工作 = max(0, 当日在岗 - 休息)`。
4. `正常工时 = min(有效工作, 每日标准工时)`。
5. `工作日加班 = max(0, 有效工作 - 每日标准工时)`。

`OvertimeBreakdown` 增加 `workdayOvertime`，总加班为早到、晚走、工作日和休息日加班之和。

## 排班编辑界面

工作地点的“常规安排”调整为：

- 正常工时开关；
- 工作日规则选择器；
- 仅在“自定义每周工作日”下显示带完整说明的星期选择器；
- 工时模式选择器；
- 固定模式显示上下班时间；
- 弹性模式显示每日标准工时；
- 两种模式都显示休息时长选择器，按 0.5 小时递增。

排班发生变化时使用居中的系统 `.alert`，不再使用 `.confirmationDialog` 气泡。点击保存时捕获影响数量，弹窗存续期间不随后台刷新改变：

> 当前地点共有 N 条未删除记录。
> 仅今后：已有 N 条记录保持原排班，下次到达时生效。
> 全部历史：按新排班重新计算 N 条记录，包含进行中的记录。

按钮为“仅今后”“全部历史（N 条）”“取消”。

影响数量与实际批量修正复用同一个会话筛选方法：当前地点、未软删除，包含进行中，排除其他地点。这里的 N 表示统计结果会被重新计算的记录数；“仅今后”为兼容旧记录而写入旧快照不算作结果变化。

## 历史展示与性能

- 历史页每次状态更新只生成一次展示快照，预先索引事件、地点、来源、排班、加班和跨天结果。
- 卡片接收已计算结果，不再逐卡重新构建全量字典或线性扫描全部事件。
- 保留两列瀑布流和分页，但不再按奇偶固定分栏。使用可测试的权重分配器，将下一张卡放入当前估算高度较短的一列；权重包含卡片基础内容、时段数量、跨天和加班附加行。
- 类型筛选、整卡点击、来源标记和详情能力保持不变。

## 原子性与错误处理

- 地点字段、排班字段和历史修正事件继续通过一次 SwiftData 保存提交，失败时整体回滚。
- “全部历史”的展示数量和写入目标来自相同筛选结果。
- 排班不完整、标准工时非法、固定上下班起止相同或时区无效时禁止保存。
- 法定工作日数据缺少年份时回退普通周末规则，不访问网络，也不阻塞记录和历史展示。

## 测试与验证

### 领域测试

- 2026 法定节假日整段为休息日加班。
- 2026 调休周末按正常工作日计算。
- 自定义星期规则保持旧行为。
- 固定班次正确扣除一次休息，夜班不重复扣除。
- 弹性 8 小时、休息 3 小时、在岗 11 小时得到 0 加班。
- 弹性跨多日逐日扣除；休息日不扣休息，整段为加班。
- 旧快照缺少新字段时仍按旧口径计算。

### 用例与存储测试

- 影响数量包含当前地点的已结束和进行中会话。
- 影响数量排除软删除和其他地点。
- 弹窗数量与“全部历史”实际生成的修正事件数量一致。
- “仅今后”不改变已有统计；“全部历史”按新模式重算。
- 旧备份可读取，新字段可往返。

### UI 与性能验证

- 排班范围使用居中弹窗，显示正确数量和三项操作。
- 工作日规则、工时模式、标准工时和休息时长能正确回填。
- 休息时长以 0.5 小时递增。
- 历史页两列末尾没有明显单侧长空白。
- 真机同一份 42 会话、116 事件数据上复测滚动流畅度。
- 完整 `TimeTraceTests`、Debug 构建和 `git diff --check` 通过；最终真机核对 9 月 21 日重算结果。
